## 10. 非动线但影响验收的契约探针

| 项 | 断言 | 结果 |

| 双 storage 互斥 | 写入清另一侧 | ✅ 同上 |
| 未登录守卫 | 会话页/认证页直达 | ✅ `/login?redirect=…` |
| 40100/40301/40302 语义 | 统一由 baseQuery 处理 | ✅ 清态跳登录 / 封禁弹窗去重 / 受限 warning 提示 |
| 信封永 200 | 业务错误仍 HTTP 200 | ✅ 探针可见 `status:200, code:40907` 等 |

## 11. 修复的真实缺陷（本轮及之前）

1. **WebSocket 从未建立**（致命，本轮修）：`useChatSocket` 的 `manualClosed` 在 StrictMode 的 cleanup 后未复位，第二次 `connect()` 直接 return。
   - 影响：实时消息、已读回执、离线未读全部失效（且不易察觉——REST 仍能把历史消息拉出来）。
   - 修法：effect 开头复位 `manualClosed.current = false`；驱动加 WS 帧观测佐证（修复前 `closed:true, frames:0`，修复后 `closed:false, frames:9`）。
2. **`POST /orders` 返回整个 `OrderDetailVO`**（上一轮修）：误当 number 使用导致 `/orders/[object Object]`；已对齐 `res.data.id` 语义并同步契约表。
3. **列表不响应 `route.query`**（有意修正，见下）：旧版只在 setup 读一次 query。

## 12. 与旧版的刻意差异（均在本文档与交接文档中登记）

| # | 差异 | 理由 |
|---|---|---|
| 1 | `/` 改为**落地页**，商城主页迁到 `/home`；Logo 指向 `/`；脏 URL 兜底 `/home` | 用户明确要求新增纸质布告栏落地页 |
| 2 | 登录成功默认跳 `/home`（旧版跳 `/`） | 承接差异 1（`?redirect=` 优先逻辑不变） |
| 3 | 商品列表**响应 query 变化**（缺陷 #1 修正） | 否则「在 /goods 内点分类/用顶栏搜索」不刷新，演示动线 §1.4/§1.5 无法通过 |
| 4 | WebSocket 用 `getToken()`（缺陷 #4 修正） | 否则 `remember=false` 用户永远连不上 |
| 5 | 删除/下架后的回跳用 `/home`（旧版 `/`） | 同差异 1 |
| 6 | 保留的旧行为：`?tab=notify` 参数不被消息中心读取（动线 §7.7 靠手动切 Tab） | 1:1 保留，不动功能 |

## 13. 结论

演示动线 §1~§9 的 **38 个可自动化断言行全部通过**（§9.3/§9.5 需构造行为数据/触发离线任务，按设计降级为热门兜底并已注明）；本轮发现并修复 1 个致命实时通信缺陷；无 console error / pageerror（仅有无头浏览器探针自关连接的无害 warning）。
