# 命名与工程规范

> 本文档约束整个工程的命名方式，新代码一律遵守；与 PRD 冲突时以 PRD 为准并回改本文档。

## 1. 仓库与工程

- 仓库根目录：中文项目名（`校园二手平台交易系统`），代码子目录一律英文：`backend/`、`frontend-web/`、`frontend-admin/`、`docs/`。
- 后端 artifactId：`campus-market`；前端包名：`campus-market-web` / `campus-market-admin`（kebab-case）。
- Java 包名全小写：`com.campus.market.<layer>`。

## 2. 后端（Java / Spring Boot）

| 对象 | 规范 | 示例 |
|------|------|------|
| 包结构 | 按层分包：common / config / security / controller / service / mapper / entity / dto / vo | — |
| 类名 | 大驼峰，按层加后缀 | `UserController`、`UserService`、`UserServiceImpl`、`UserMapper`、`GoodsPublishDTO`、`GoodsDetailVO` |
| 方法名 | 小驼峰，动词开头 | `publishGoods`、`cancelOrder`、`listByCategory` |
| 常量 | 大写下划线 | `MAX_IMAGE_COUNT`、`TYPE_ACCESS` |
| 枚举 | 类名大驼峰，成员全大写 | `OrderStatus.PENDING_CONFIRM` |
| 配置属性类 | Xxx + Properties | `JwtProperties`、`CreditProperties` |
| DTO / VO | 请求 XxxDTO，响应 XxxVO | — |

### REST 接口

- 统一前缀 `/api`；后台接口 `/api/admin/**`。
- 资源用名词复数、多词 kebab-case：`/api/goods`、`/api/want-posts`、`/api/verify-code/send`。
- 动作放子路径动词：`POST /api/orders/{id}/cancel`、`POST /api/orders/{id}/confirm`。
- 查询参数小驼峰：`?pageNum=1&categoryId=3&minPrice=10`。
- 响应统一 `{ code, message, data }`；code=0 成功，分段见 `ErrorCode`。
- 时间字段统一 `yyyy-MM-dd HH:mm:ss`（JacksonConfig 已全局配置）。

### Redis key

`campus:market:<模块>:<业务>:<标识>`，如 `campus:market:auth:code:{email}`、`campus:market:rec:hot:goods`。

### 注释与需求映射

类级 Javadoc 需标注对应 PRD 需求编号（如 `PRD GDS-01`）或章节号（如 `PRD §5.3`），保证代码可追溯到需求基线。

## 3. 数据库（与《数据库设计文档.md》v1.1 / sql/schema.sql 对齐）

- 数据库名：`campus_secondhand`；表名单数 snake_case，**v1.1 共 27 张**（PRD §8 实体 + tag/goods_tag/goods_want/order_no_seq 等）；`order` 因 MySQL 保留字改名 `order_info`。
- 字段 snake_case；主键 `id BIGINT UNSIGNED AUTO_INCREMENT`；时间字段 `created_at` / `updated_at`。
- **不物理删除**：内容类数据状态值软删（如 `goods.status=DELETED`），且必须记录 `deleted_at` / `deleted_by_type` / `deleted_by` / `delete_reason`（v1.1 T4）。
- 外键策略（v1.1 T3）：核心关系建**物理外键**（共 41 条）；多态/审计/跳转类引用保持逻辑外键 + 应用层校验。
- 索引：普通 `idx_<表>_<字段>`，唯一 `uk_<表>_<字段>`，全文 `ft_<字段>`。
- 实体类名大驼峰对应表名：`goods` → `Goods`、`want_post` → `WantPost`、`order_info` → `OrderInfo`；实体层共 **27 个实体类**。
- 角色值口径：数据库存大写 `SUPER/AUDITOR/OPERATOR`；代码注解、JWT 载荷、前端一律小写 `super/auditor/operator`，登录签发 token 时由后端统一转小写。

## 4. 前端（Vue 3）

> **状态更新（2026-10-17）**：前台与后台均已有 React 版（`frontend-web-react/`、`frontend-admin/`），两套并存；Vue 版（本节的 `frontend-web/`）保留不动。
> **React 版命名规范见 §4bis**，新代码一律按 §4bis 执行；仅在维护 Vue 版旧代码时参考本节。

| 对象 | 规范 | 示例 |
|------|------|------|
| 组件文件 | 大驼峰 + `.vue` | `GoodsCard.vue` |
| 页面文件 | `views/<模块>/<名称>View.vue` | `views/goods/GoodsDetailView.vue` |
| 组合式函数 | `use` 前缀小驼峰 | `useUserStore` |
| Pinia store | `stores/<模块>.js`，导出 `useXxxStore` | `stores/user.js` |
| API 模块 | `api/<模块>.js`，导出小驼峰函数 | `api/user.js` |
| 路由 | path 小写 kebab-case；name 大驼峰 | `/sensitive-word`，name `SensitiveWord` |
| 前端常量 | 大写下划线 | `SUCCESS_CODE`、`AUTH_EXPIRED_CODES` |
| CSS 类名 | 小写 kebab-case | `.page-title`、`.placeholder-card` |
| 目录 | 一律英文小写：`components/`、`layouts/`、`stores/`、`views/`、`api/`、`utils/`、`styles/` | — |

## 4bis. 前端（React，现行）

以 `frontend-web-react/` 与 `frontend-admin/` 为基准（两者结构同构）：

| 对象 | 规范 | 示例 |
|------|------|------|
| 页面文件 | 大驼峰 + `Page.tsx`，目录 `pages/<模块>/` | `pages/goods/GoodsDetailPage.tsx` |

| hooks | `use` 前缀小驼峰，按域放 `features/<域>/` 或 `components/` | `features/msg/useChatSocket.ts` |

| `data-testid` | 小写 kebab-case；登录/注册/认证页的 10 个锚点**不得改名** | `login-username`、`verify-code` |
| 目录 | `api/ app/ components/ features/ layouts/ lib/ pages/ router/ styles/` | — |

## 5. Git（init 之后生效）

- **分支约定（用户指定）：主分支为 `master`，一切推送均推 `master`**；日常开发可另开 `dev` 或功能分支 `feat/<模块>`（如 `feat/order`），完成后合回 `master`。
- 提交信息：`<type>(<scope>): <desc>`，type ∈ feat / fix / docs / refactor / test / chore。
  示例：`feat(order): 订单状态机与超时取消定时任务`。
- 禁止提交：`node_modules/`、`target/`、`dist/`、`upload/` 内容、`.env`、真实密钥（见根 .gitignore）。
